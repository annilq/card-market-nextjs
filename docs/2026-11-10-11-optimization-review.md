## 二、11-10 的优化

### 2.1 媒体响应缓存 30 天

- 文件：`src/collections/Media.ts`
- 优化前：Payload 媒体响应不带 `Cache-Control`，浏览器回访会重新下载图片。Lighthouse 实测约 66 KiB 重复下载。
- 优化后：`Cache-Control: public, max-age=2592000, stale-while-revalidate=86400`
- 影响：上传后的文件名带批次后缀，内容基本稳定，适合长缓存。
- 注意：如果后台原地替换同名文件，用户最多可能看到 30 天旧图。

### 2.2 顶部 logo 补宽高

- 文件：`src/components/layout/SiteHeader.tsx`
- 优化前：`<img>` 没有 `width` / `height`，图片加载前不占位。
- 优化后：使用设置里的图片尺寸，缺省 `300 × 57`。
- 影响：降低 CLS，减少首屏布局跳动。

## 三、11-11 的优化

### 3.1 卡牌状态从固定枚举改为可编辑分类

- 提交：`e74d09c`
- 新增集合：`src/collections/CardStatuses.ts`
  - 字段：名称、排序、启用、高亮标识 `accent`
  - 接入角色权限矩阵，模块名为 `card-statuses`
- 卡牌字段变化：
  - 优化前：`cardStatus` 是 `select`，固定值 `raw` / `packaged`
  - 优化后：`cardStatus` 是关系字段，指向 `card-statuses`
- 前台变化：
  - 卡片列表、详情、筛选面板都改为读取状态名称与高亮标识
  - 原来写死的「裸卡 / 有包装」文案和样式被移除
- 数据迁移：`20261110_221000_card_statuses`
  - 存量 `raw` 落为「裸卡」
  - 存量 `packaged` 落为「有包装」，并保留原来的强调样式
- 兼容性影响：
  - REST / GraphQL 里的 `cardStatus` 从字符串变成关系 ID
  - 前台筛选 URL 的 `status` 参数从 `raw,packaged` 变成状态 ID
  - 外部调用方如果依赖旧枚举，需要同步修改

### 3.2 新增「不减额买取」

- 提交：`e74d09c`
- 新字段：`isNoDeduction`
- 规则：
  - 与 `isHighValue` 互斥
  - 后台两个复选框即时联动，服务端 `beforeValidate` 也会拦截 API 写入
  - 两类卡牌都进入首页「高价买取」横条
  - 卡片徽章按类型显示「高价买取」或「不减额买取」
- 数据迁移：`20261110_234500_no_deduction_buyback`
- 筛选变化：`hv=1` 现在表示「高价买取或不减额买取」

### 3.3 买取排序号与首页自动轮播

- 提交：`182f3d1`
- 卡牌新增 `sort` 字段，仅对高价买取 / 不减额买取卡牌生效。
- 排序规则：
  - `sort` 升序
  - 未设序号按 `NULLS LAST` 垫后
  - 同序号按创建时间倒序
  - 首页最多取 10 张
- 首页横条从静态滚动改为客户端自动轮播：
  - 每 4.5 秒滚动一张卡
  - 悬停、聚焦、拖拽时暂停
  - 松手 1.2 秒后恢复
  - 尊重 `prefers-reduced-motion`
  - 内容没有溢出视口时不自动滚动
- 后台排序字段增加说明气泡，公告与卡牌共用 `SortFieldLabel`。
- 数据迁移：`20261111_003500_buyback_sort`

### 3.4 筛选与搜索

- 提交：`e74d09c`
- 卡牌状态筛选：
  - 优化前：固定两个复选框
  - 优化后：使用 `card-statuses` 集合的数据，支持任意新增状态
- 搜索：
  - 前台列表与后台列表都支持卡名、收藏编号、稀有度名称
  - 稀有度使用关系路径 `rarity.name`，由数据库 JOIN 后匹配
- 后台表单联动：
  - 未选 IP 时不再一次性拉出全部系列
  - 未选系列时不再一次性拉出全部子系列

### 3.5 公告置顶与排序

- 提交：`e74d09c`，首页名额在 `e6df500` 再调整
- 优化前的问题：
  - 先按时间取前 N 条，再在结果内排置顶
  - 不在时间窗口内的置顶公告永远进不了首页
  - 未置顶公告的 `sort` 也可能干扰排序
- 优化后：
  - 支持同时置顶多条
  - 置顶组内按「置顶排序」升序，再按发布时间倒序
  - 未置顶组只按发布时间倒序，`sort` 被忽略
  - 发布时间为空时回退到创建时间
  - 排序在内存完成，避免数据库 `NULLS FIRST` 问题
- 首页规则最终状态：
  - `e74d09c`：最多 5 条，置顶最多 2 条
  - `e6df500`：改为最多 3 条，置顶优先占满 3 个名额
  - 置顶超过上限时，多出来的公告回到时间序参与补位
- 列表性能：
  - `depth` 从 1 降为 0
  - 列表不再渲染公告正文，详情页单独获取完整文档

  - 已保存的卡牌可修改后 PATCH 更新
  - 新建成功后自动跳到下一张待填图片；更新已存卡不跳走
- 导航与安全：
  - 上一张 / 下一张

  - 窄屏改为纵向滚动布局

- 提交：`e74d09c`

### 3.9 单一管理员约束

- 提交：`e74d09c`
- 规则：

  - 管理员角色不能分配给第二个账号

- 提交：`b92d8e0`

## 五、兼容性与注意事项

1. **卡牌状态 API 变化**
   - `cardStatus` 从字符串枚举变为关系 ID。
   - 依赖 `raw` / `packaged` 的外部脚本或接口调用需要修改。

2. **筛选 URL 变化**
   - `/cards?status=raw` 这类旧链接不再匹配。
   - 新格式是 `/cards?status=<card-status-id>`。

3. **买取筛选变化**
   - `hv=1` 现在同时包含「高价买取」和「不减额买取」。

4. **媒体缓存**
   - 浏览器缓存 30 天。
   - 后台原地替换同名文件时，用户可能继续看到旧图。

5. **首页公告数量**
   - 11-11 当天先改为 5 条，随后在同一天改为 3 条。
   - 对比最终效果时以 3 条为准。

6. **批量上架权限**
   - 账号必须同时拥有 `cards.create` 和 `media.create`。
   - 缺少任一权限会被重定向到 `/admin/unauthorized`。

7. **批量上架与买取字段**
   - 批量上架表单目前只提供「高价买取」。
   - 「不减额买取」和买取排序号仍需在单卡编辑页设置。
