后台模块说明

这份文档按业务顺序介绍后台每个模块的作用：先准备素材和分类，再建卡牌商品，然后维护前台展示的内容，最后管理系统账号与权限。后台所有数据都按上述五个分组归类，左侧导航按分组排列。

分组：素材

图片 Media

所有图片素材的统一存放处。卡牌图片、门店照片、轮播图都从这里选。前台页面直接引用媒体地址，所以图片对匿名访客始终可读，避免页面出现裂图；上传和删除按角色权限控制。

关键字段

  • alt（替代文本）：必填，用于无障碍和图片加载失败时的占位文字。

需要知道的行为

  • 上传时原图自动转成 webp 压缩体积。
  • 同时生成三档尺寸：thumb（宽 480）、card（宽 800）按原图比例等比缩放，卡面不会被裁；banner（1920×900）按横幅比例居中裁剪。引用图片时按场景选对应尺寸。
  • 支持设置焦点位置（focal point），保证 banner 裁剪后主体不被切掉。
分组：分类

这一组是卡牌的筛选维度。卡牌在前台按 IP、系列、子系列、稀有度四层筛选，这四个集合就是这些维度的来源。它们不用"发布状态"，而是用"启用"开关来控制是否在前台出现。任何改动都会立刻让筛选维度缓存失效。

IP / 大类 IPs

卡牌所属的最高层分类，例如宝可梦、游戏王、龙珠。卡牌必须先归属到一个 IP。

关键字段

  • name（名称）：必填，例如"宝可梦"。
  • sort（排序）：控制前台筛选器里的显示顺序。
  • enabled（启用）：关闭后该 IP 及其下卡牌不再出现在前台筛选。

系列 Series

隶属于某个 IP 的第二层分类。建系列时必须先选好所属 IP。

关键字段

  • name（名称）：必填。
  • ip（所属 IP）：必填，关联到 IP / 大类。

子系列 Sub-series

隶属于某个系列的第三层分类。即使某个 IP 实际只有两层（没有子系列），也必须建一个空壳子系列占位。

子系列必填：空值（NULL）会破坏卡牌"IP + 系列 + 子系列 + 编号"的组合唯一约束，导致重复卡牌无法被拦住。两层结构的 IP 也要建一个占位子系列。

稀有程度 Rarities

卡牌的稀有度维度，例如 N、R、SR、SSR。只有名称、排序、启用三个字段，相对最简单。

依赖关系：卡牌 → 子系列 → 系列 → IP。建卡牌前请先确保这四个维度都已就绪。

分组：商品

卡牌 Cards

商品本体，也是前台最核心的内容。一张卡牌把上面四个分类维度、价格、图片和描述聚合在一起。

关键字段

  • name（卡牌名称）：必填。
  • ip / series / subSeries：三个联动下拉。选了 IP 后系列只显示该 IP 下的，选了系列后子系列只显示该系列下的。
  • rarity（稀有程度）：关联到稀有度维度。
  • code（收藏编号）：例如 123/197，同一 IP + 系列 + 子系列下编号不能重复。
  • price（卖价）：数字，前台按价格展示。
  • images（卡牌图片）：可多选，从"图片"集合里挑。
  • isHighValue（高价买取）：纯标记，供前台"只看精品"筛选使用。
  • cardStatus（卡牌状态）：裸卡 / 有包装，记录卡片品相类型。
  • status（状态）：草稿 / 已发布 / 已归档，三态生命周期，只有已发布才在前台可见。
编号去重：系统用"IP + 系列 + 子系列 + 编号"组合判断是否重复，重复会直接报错。子系列必须填，正是为了这套去重能正常工作。

批量上架 Bulk cards

一次上传多张卡图、逐张录入卡牌信息的快捷页面。入口在左侧「商品 → 批量上架」，账号需要同时拥有「卡牌」新增和「图片」新增权限。

操作流程

  1. 点「添加文件」或把图片拖进左侧区域。图片直接上传到对象存储，列表里显示每张图的排队、上传、处理状态。
  2. 点左侧图片，在右侧填卡牌名称、分类、编号、卖价、状态和描述；替代文本默认取文件名，可修改。
  3. 保存成功会弹出提示并自动跳到下一张待填图片。左侧列表用「已保存」（绿色）和「未填写」（琥珀色）标记每张图的进度。

需要知道的行为

  • 「批量填充分类」把 IP、系列、子系列、稀有度和发布状态一次套到所有未保存的图片，不会改动已保存的卡牌。
  • 已保存的卡牌可以继续修改字段，按钮会变成「更新卡牌」，保存时更新原记录而不是新建。
  • 快捷键：⌘/Ctrl + Enter 保存当前卡牌，Alt + ←/→ 切换图片。
  • 有未保存内容时关闭或刷新页面会弹出确认；移除已填写但未保存的图片也会先确认。
  • 编号重复的报错显示在「收藏编号」下方，改号后再存即可。
移除一张已上传但未保存的图片会同时删除对应素材；已保存卡牌使用的图片不会被删除。批量上架与普通卡牌表单写入同一张表，保存后立即出现在「卡牌」列表。
分组：内容

这一组承载前台展示的各类内容：首页轮播、公告、门店、合规信息页，以及访客提交过来的留言。

首页轮播 Banners

首页顶部的轮播图，只有一个槽位。没有定时上下线功能，轮播间隔由前端常量控制。

关键字段

  • title（标题）、description（描述）：轮播上的文案。
  • image（轮播图）：必填，从"图片"集合选。
  • link（跳转链接）：站内路径（如 /cards）或外部 URL。
  • status（状态）：仅已发布才出现在首页。

公告 Announcements

站点公告。前台可见条件是"已发布"且"发布时间为空或已到时间"；排序上置顶优先，其次按发布时间倒序。

关键字段

  • title（标题）、body（正文）：富文本。
  • publishedAt（发布时间）：留空表示立即展示，填未来时间表示定时发布。
  • isPinned（置顶）：勾选后排在公告列表最前。

门店 Shops

线下门店信息，含位置、营业时间、电话和照片。

关键字段

  • name（门店名称）、address（地址）、businessHours（营业时间）、phone（电话）。
  • geo（位置）：地图选点或搜索地址，保存后自动把经纬度写入 lat / lng（这两列只读，由地图选点生成）。
  • image（门店图片）：从"图片"集合选。

审核信息页 Info pages

四个固定的合规信息页：运营信息、个人信息收集、利用规则、数据使用。页面标识由代码固定，后台只能维护标题和正文。

关键字段

  • pageKey（页面标识）：四个固定值之一，对应前台 /info/<标识>，不要随意改。
  • title（标题）、body（正文）：富文本。
未发布时前台仍返回 200，并提示"尚未发布"，不会报 404，方便审核期间预览。

访客留言 Messages

访客从前台表单提交的咨询，按工单流转，不是普通内容。访客可匿名提交，不登录也能发。

关键字段

  • content（留言内容）：必填，最多 2000 字。
  • contactName（联系人）、contactInfo（联系方式）：邮箱 / 电话 / 微信，选填。
  • card（关联卡牌）：访客从卡牌详情点"咨询此卡"时自动带入。
  • status（处理状态）：新 / 已处理 / 已归档 / 已标记垃圾四个工单态，列表里用颜色胶囊显示，便于一眼看到待处理的新留言。
匿名留言只保留上述指定字段，状态强制为"新"，不能用内容集合的发布状态。
分组：系统

这一组管理谁能登录后台、以及每个人能做什么，是账号与权限层。

角色管理 Roles

自定义后台角色并配置权限矩阵。只有超级管理员能增删改角色本身。

关键字段

  • name（角色名称）：唯一。
  • isAdmin（超级管理员）：勾选后忽略权限矩阵，拥有全部模块的全部操作。
  • permissions（模块权限）：对普通角色生效的矩阵。逐模块勾选"查看 / 新增 / 编辑 / 删除"。
勾了超级管理员后权限矩阵自动隐藏且不再生效，无需逐项配置。

用户 Users

后台登录账号，用邮箱加密码登录。账号的权限来自所绑定的角色。

关键字段

  • name（姓名）、phone（电话）：电话用于联系，非收货信息。
  • avatar（头像）：从"图片"集合上传，显示在后台右上角账户图标。
  • role（角色）：关联到"角色管理"里的记录。新建账号时过滤掉超级管理员角色，只能选普通角色；编辑已有账号时放开。
  • forcePasswordChange（首次登录强制改密）：隐藏字段，由系统控制，不在此处手动勾。
角色字段只有超级管理员能改，防止普通用户把自己提权成管理员。数据库为空时注册的第一个用户自动成为超级管理员；之后由管理员新建的账号默认强制下次登录改密。当前版本没有自助找回密码，重置密码只能由管理员在后台操作。
